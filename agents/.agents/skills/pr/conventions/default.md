# PR Convention: default

## 제목 형식

```
[{issue_number}] #{issue-number} {제목}
```

| 타입 | 용도 | Label |
|------|------|-------|
| `FEAT` | 새 기능 | `✨ feat` |
| `FIX` | 버그 수정 | `🐛 bug` |
| `HOTFIX` | 프로덕션 긴급 수정 | `🚨 hotfix` |
| `CHORE` | 빌드, 의존성, 설정 | `🔧 chore` |
| `REFACTOR` | 기능 변경 없는 코드 개선 | `♻️ refactor` |
| `TEST` | 테스트 코드 | `✅ test` |
| `DOCS` | 문서 수정 | `📝 docs` |

**예시:**
```
[#42] PostgreSQL Advisory Lock으로 차 대절 동시성 제어
[#7] 탈퇴 후 토큰 만료 안 되는 버그 수정
```

---

## Body 구조

```markdown
## 작업 내용

{변경한 것과 이유. 코드 수준의 핵심만.}

## 구현

- {항목}
- {항목}

## 테스트

{테스트 방법 또는 N/A}

Closes #{issue-number}
```

---

## 문체 가이드

PR body는 **합쇼체(~습니다/~됩니다)**로 작성한다.

**핵심 원칙:**
- 왜 바꿨는지 먼저, 무엇을 바꿨는지는 구현 항목으로
- 한 문장에 한 가지만
- 결과가 명확하면 이유 설명 생략 가능

**금지 표현:**
- "~를 통해 ~를 개선" → "~개선됩니다"
- "해당 PR은", "이번 작업에서는"
- "전반적인", "효율적인", "최적화된"
- "이를 통해", "따라서"
- 종결어미를 `~됨.`, `~함.` 등 반말체로 끝내는 것

**작업 내용 예시:**

나쁜 예:
```
동시 예약 요청 시 잔여 좌석이 음수가 됨. Advisory Lock 걸어서 막음.
```

좋은 예:
```
동시 예약 요청 시 잔여 좌석이 음수가 됩니다. 트랜잭션 단위로 Advisory Lock을 걸어 막습니다.
```
