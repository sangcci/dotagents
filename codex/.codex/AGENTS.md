# Global Agent Guide

## 기본 응답 스타일

- 사용자가 질문한 범위에만 정확하고 간결하게 답한다. 요청하지 않은 배경 설명, 추가 제안, 후속 질문은 생략한다. 결론부터 말하고, 정확성에 필요한 조건과 불확실성만 덧붙인다. 자세한 설명은 요청받았을 때 제공한다.

- 사용자에게 보내는 답변과 진행 상황 메시지에는 [attention-kind](skills/attention-kind/SKILL.md) 스킬을 기본으로 적용한다.
- 한국어 답변과 한국어 결과물에는 [fluent-korean](skills/fluent-korean/SKILL.md) 스킬도 기본으로 적용한다.
- 사용자가 지정한 언어, 분량, 문체와 결과물 형식을 우선한다. 답변을 간결하게 하더라도 필요한 정보나 작업, 검증을 생략하지 않는다.

## 답변 문장부호

- 사용자에게 보내는 모든 답변과 진행 상황 메시지에서 유니코드 U+00B7 가운데점을 사용하지 않는다.
- 항목을 나열할 때는 쉼표, 접속사 또는 줄바꿈을 사용한다.
- 답변을 보내기 전에 U+00B7 문자가 포함되지 않았는지 확인한다.

## Context-efficient tool output

도구와 명령의 전체 출력을 대화 context에 불필요하게 적재하지 않는다. 작업의 정확성을 유지하면서 판단과 다음 행동에 필요한 정보만 노출한다.

### 검증 명령

- build, test, lint, formatting, documentation generation처럼 출력이 긴 검증 명령은 전체 stdout과 stderr를 임시 로그 파일에 저장한다.
- 검증에 성공하면 명령의 목적과 성공 여부만 간결하게 출력한다.
- 검증에 실패하면 실패한 task 또는 test, 최초의 유의미한 오류와 원인 분석에 필요한 주변 로그만 출력한다.
- 실패 원인이 불분명하면 저장한 로그를 `rg`, `sed`, `tail` 등으로 단계적으로 좁혀 읽는다. 전체 로그를 한 번에 출력하지 않는다.
- warning은 현재 변경이나 결과에 영향을 주는 경우에만 context에 포함한다.
- 전체 로그가 필요해도 먼저 저장 위치를 알리고, 필요한 범위를 선택적으로 읽는다.

### 파일과 검색 결과

- 파일을 읽기 전에 `rg`, `rg --files`, `wc -l` 등으로 대상과 범위를 좁힌다.
- 관련성이 확인되지 않은 대형 파일, generated artifact와 전체 build log를 한 번에 출력하지 않는다.
- 필요한 line range와 일치 항목만 읽되, 선택한 지침 파일과 계약 문서를 생략 없이 읽어야 한다는 기존 규칙을 우선한다.
- 결과가 반복되면 원문 전체 대신 개수, 파일 목록과 대표 사례를 먼저 확인한다.
- 이미 확인한 동일한 출력은 상태가 변경되지 않은 한 다시 context에 적재하지 않는다.

### 실패 정보 보존

- 출력 축약을 이유로 실패를 성공처럼 보고하거나 오류를 숨기지 않는다.
- 임시 로그에는 원본 출력을 보존하고, 진단에 필요하면 추가 범위를 읽는다.
- token, cookie, password, secret과 개인정보가 로그에 포함될 가능성이 있으면 대화에 출력하기 전에 제외하거나 마스킹한다.

### 사용자 보고

- 최종 응답에는 실행한 주요 검증, 성공·실패 여부와 남아 있는 위험만 설명한다.
- 사용자가 요청하지 않았다면 성공한 build와 test의 task별 전체 출력을 반복하지 않는다.
