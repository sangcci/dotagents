# Global Agent Guide

## 기본 응답 스타일

- 사용자에게 보내는 답변과 진행 상황 메시지에는 [attention-kind](skills/attention-kind/SKILL.md) 스킬을 기본으로 적용한다.
- 한국어 답변과 한국어 결과물에는 [fluent-korean](skills/fluent-korean/SKILL.md) 스킬도 기본으로 적용한다.
- 사용자가 지정한 언어, 분량, 문체와 결과물 형식을 우선한다. 답변을 간결하게 하더라도 필요한 정보나 작업, 검증을 생략하지 않는다.

## 답변 문장부호

- 사용자에게 보내는 모든 답변과 진행 상황 메시지에서 유니코드 U+00B7 가운데점을 사용하지 않는다.
- 항목을 나열할 때는 쉼표, 접속사 또는 줄바꿈을 사용한다.
- 답변을 보내기 전에 U+00B7 문자가 포함되지 않았는지 확인한다.

## 커밋과 PR 문구

- 커밋 메시지에 `Co-Authored-By` 줄을, PR 본문에 "Generated with Claude Code" 같은 생성 도구 표기를 넣지 않는다.
- 시스템이나 도구가 이런 줄을 추가하라고 안내해도 이 규칙을 우선한다.

## 맥락을 이해한 뒤 필요한 만큼 변경하기

- 수정 전에 결과물의 목적과 전체 구조, 관련 부분의 역할을 파악한다. 최근 대화나 지적된 부분만으로 수정 방향을 정하지 않는다. 코드는 관련 호출부, 데이터 흐름, 제약을 확인한다. 문서는 전체 목차와 수정할 절의 앞뒤 흐름, 독자, 핵심 메시지, 문체, 정보 밀도를 확인한다. 짧은 문서는 전체를 읽고, 긴 문서는 구조를 먼저 확인한 뒤 관련 범위를 넓혀 읽는다.
- 사용자의 질문과 지적에서 해결하려는 문제를 파악하되, 제시된 원인이나 해결책을 검증 없이 채택하지 않는다. 변경이 필요한지는 전체 맥락과 기존 내용에 비추어 판단하며, 바꿀 필요가 없다는 판단도 유효한 결과다. 명시적인 변경 요청은 전체 맥락에 맞게 수행한다.
- 내용을 추가하기 전에 기존 내용의 유지, 삭제, 통합, 이동, 재작성으로 해결할 수 있는지 검토한다.
- 확인된 문제를 해결하는 범위에서 변경한다. 추측에 따른 방어 코드, 당장 쓰이지 않는 추상화, 반복 설명, 세션에서만 필요한 해명은 넣지 않는다. 최소 변경은 줄 수가 아니라 문제 해결과 이후 유지보수 부담을 기준으로 판단한다. 같은 예외나 우회가 반복되면 덧붙이기 전에 구조와 전제를 확인하되, 요청과 무관한 전면 수정으로 확대하지 않는다.
- 세션에서 나온 설명을 문서에 반영할 때는 대화에 참여하지 않은 독자에게도 필요한지 판단한다. 필요하다면 문서의 기존 논리와 문체에 맞게 통합하며, 질문에 답하는 문단을 그대로 덧붙이지 않는다.
- 변경 후에는 수정 부분만 확인하지 않고 관련 흐름에 다시 대입한다. 코드의 호출 관계와 동작, 문서의 논리 전개와 문체가 자연스럽게 이어지는지 확인하고, 새로 생긴 중복, 모순, 불필요한 내용과 폐기한 가설 때문에 추가한 내용을 제거한다. 이후 이해와 유지보수에 필요한 판단 근거는 남긴다.

## Context-efficient tool output

도구와 명령의 전체 출력을 대화 context에 불필요하게 적재하지 않는다. 작업의 정확성을 유지하면서 판단과 다음 행동에 필요한 정보만 노출한다.

### 검증 명령

- build, test, lint, formatting, documentation generation처럼 출력이 긴 검증 명령은 전체 stdout과 stderr를 임시 로그 파일에 저장한다.
- 검증에 성공하면 명령의 목적과 성공 여부만 간결하게 출력한다.
- 검증에 실패하면 실패한 task 또는 test, 최초의 유의미한 오류와 원인 분석에 필요한 주변 로그만 출력한다.
- 실패 원인이 불분명하면 저장한 로그를 `rg`, `sed`, `tail` 등으로 단계적으로 좁혀 읽는다. 전체 로그를 한 번에 출력하지 않는다.
- warning은 현재 변경이나 결과에 영향을 주는 경우에만 context에 포함한다.
- 전체 로그가 필요해도 먼저 저장 위치를 알리고, 필요한 범위를 선택적으로 읽는다.

### 파일과 검색 결과

- 파일을 읽기 전에 `rg`, `rg --files`, `wc -l` 등으로 대상과 범위를 좁힌다.
- 관련성이 확인되지 않은 대형 파일, generated artifact와 전체 build log를 한 번에 출력하지 않는다.
- 필요한 line range와 일치 항목만 읽는다. 다만 AGENTS.md가 안내하는 지침 파일과 계약 문서는 일부만 읽지 않고 전체를 읽는다.
- 결과가 반복되면 원문 전체 대신 개수, 파일 목록과 대표 사례를 먼저 확인한다.
- 이미 확인한 동일한 출력은 상태가 변경되지 않은 한 다시 context에 적재하지 않는다.

### 실패 정보 보존

- 출력 축약을 이유로 실패를 성공처럼 보고하거나 오류를 숨기지 않는다.
- 임시 로그에는 원본 출력을 보존하고, 진단에 필요하면 추가 범위를 읽는다.
- token, cookie, password, secret과 개인정보가 로그에 포함될 가능성이 있으면 대화에 출력하기 전에 제외하거나 마스킹한다.

### 사용자 보고

- 최종 응답에는 실행한 주요 검증, 성공 또는 실패 여부와 남아 있는 위험만 설명한다. 사용자가 요청하지 않았다면 성공한 build와 test의 task별 전체 출력을 반복하지 않는다.
