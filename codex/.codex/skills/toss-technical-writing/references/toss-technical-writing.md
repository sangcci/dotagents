# 토스 테크니컬 라이팅 공개 자료 메모

## 확인한 원칙

- 한 페이지에서는 하나만 다룬다.
- 가치를 먼저 제시한다.
- 문서를 쓰기 전 목적, 독자, 참고 자료와 예상 구조를 확인한다.
- 개요에는 문서가 무엇인지와 독자가 얻을 내용을 담는다.
- 이름만 있는 속성이나 용어는 독자가 의미를 추측하게 하므로, 의미·형식·필요한 예시를 함께 설명한다.

## 이 스킬에 적용하는 방법

- 이력서 불릿에서는 ‘무엇을 했다’보다 그 행동으로 독자 또는 팀이 얻은 변화를 먼저 쓴다.
- 하나의 불릿에 도입 배경, 여러 실행 항목, 여러 성과를 모두 넣지 않는다. 하나의 판단이나 결과로 나눈다.
- 문서 체계와 협업 흐름을 쓸 때는 도구 이름보다 팀이 어떤 정보를 같은 기준으로 다루게 되었는지 설명한다.
- 맥락이 필요한 경우에도 부정적 서사를 과장하지 않는다. 실제 장면과 중립적 표현으로 변화의 필요성을 설명한다.

## 출처

- 토스 테크, [세상에 없던 직무를 만들어가기](https://toss.tech/article/technical-writing-1): Technical Writer가 조직 안에서 문서의 목적과 독자 맥락을 다루는 사례.
