# CV Writing

독자가 지원자의 역할, 판단과 확인한 결과를 이해하도록 쓴다. 담담하게 쓰되 직접 한 행동은 분명하게 밝힌다. 표현의 강도는 근거의 범위를 넘기지 않는다.

## 적용 자료

- 작성과 문장 검토에는 [문체와 주장 범위](references/wording-and-evidence.md)를 읽는다.
- 이력서와 경력기술서에는 [이력서 작성 가이드](references/cv-style-guide.md)를 읽는다.
- 상세 포트폴리오에는 [포트폴리오 작성 가이드](references/portfolio-writing.md)를 읽는다. 이력서의 분량과 문장 틀을 그대로 적용하지 않는다.

현재 문서와 원천 자료, 사용자가 요청한 범위를 먼저 확인한다. 문서 전체의 목적과 흐름을 파악한 뒤 관련 부분을 수정한다. 기존 프로젝트 선택과 사용자의 수정은 보존한다. 스킬의 예시는 경험을 증명하는 자료로 사용하지 않는다.

## 근거부터 판단하기

문장을 쓰기 전에 다음을 구분한다. 답변에 별도 표를 항상 출력할 필요는 없다.

- 본인의 역할과 팀 전체의 작업
- 관찰한 문제와 가정한 실험 상황
- 당시 판단과 이후 추가로 검토한 대안
- 설계, 구현, 테스트 작성, 실행 결과, 배포와 운영 효과
- 확인한 사실, 본인의 해석과 미확인 사항

수치, 기간, 역할, 선택지와 결과는 제공된 자료와 사용자 설명만 사용한다. 문서 간 값이 다르면 같은 실험과 기간인지 먼저 확인한다. 충돌하는 값을 임의로 통일하지 않는다. 커밋 작성 기록은 설계 주도권이나 실제 운영 효과까지 증명하지 않는다.

근거가 부족하면 확인된 행동만 쓰거나 해당 주장을 제외한다. 핵심 사실이 없으면 묶어서 질문하고, 검토용 초안에는 `확인 필요`로 남긴다. 없는 성과 대신 검증 계획을 완료 결과처럼 쓰지 않는다. 제출용 문서에는 미확인 표시나 계획을 성과로 남기지 않는다.

## 경험과 설명 고르기

- 기술의 개수보다 해결할 문제, 선택 근거와 검증 결과가 연결되는 사례를 고른다.
- 실제로 필요했던 개선과 학습을 위한 실험을 구분한다. 기술을 먼저 선택한 이력을 문제를 먼저 발견한 서사로 바꾸지 않는다.
- 성능 개선의 필요성, 데이터 불변식, 중간 실패와 복구, 대안의 비용 중 사례를 판단하는 데 필요한 내용을 남긴다. 모든 사례에 모든 질문을 채우지 않는다.
- 실제로 비교한 대안만 검토 경험으로 쓴다. 한계와 향후 과제도 확인된 경우에만 담는다.
- 도구나 구조의 이름으로 설명을 끝내지 않는다. 무엇을 바꿨고 어떤 동작이 달라졌는지 보여준다.
- 소개는 아래 경험으로 뒷받침할 수 있는 일하는 관점으로 쓴다. 성격에 대한 자기평가나 성과 목록만으로 채우지 않는다.

## 쓰고 줄이기

문제의 필요성, 본인의 판단과 행동, 결과를 읽는 순서에 맞게 연결한다. 한 문장에 원인과 여러 조치를 몰아넣지 않는다. 필요한 맥락은 남기되 같은 구현을 제목, 본문과 결론에서 반복하지 않는다.

완결된 본문은 `했습니다`, `확인했습니다`와 같은 존댓말로 쓴다. 기술 용어를 불필요하게 풀어 쓰거나 명사를 이어 붙여 압축하지 않는다. 검증된 사실에 `같습니다`를 반복해 붙이지 않고, 근거가 없는 성과를 자신감 있는 어미로 확정하지 않는다.

사용자의 요청이 문체 수정이면 사실과 주장 범위를 보존한다. 근거 없는 부분은 매끄럽게 확정하지 말고 표시한다. 더 강한 성과나 수치를 요청받아도 사실을 추가하지 않는다.

## 최종 검토

- 프로젝트와 본인 역할을 짧게 읽고 이해할 수 있는가?
- 어떤 문제를 왜 해결했고 직접 무엇을 했는가?
- 주장에 필요한 조건과 근거가 본문이나 연결된 상세 자료에 있는가?
- 강한 단어를 완곡한 말로 바꾸는 데 그치지 않고 대상과 동작을 밝혔는가?
- 구현과 검증, PoC와 서비스 적용, 예상 효과와 운영 결과를 구분했는가?
- 원문과 비교해 사실, 수치, 날짜, 연락처와 링크를 보존했는가?
- 중복된 설명과 사례에 불필요한 형식을 제거했는가?

사용자가 요청하지 않은 코드 수정, 새 실험 실행, 파일 변환이나 외부 전송으로 작업을 확대하지 않는다. 결과를 보고할 때 실제로 확인한 범위와 남은 확인 사항을 구분한다.
