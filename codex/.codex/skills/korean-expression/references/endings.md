# 어미 체계

결과물마다 기본 어미 하나를 정하고, 기본 어미로 쓴 문장을 보충하는 내용만 명사형으로 끝낸다. 모든 문장을 명사형으로 끝내면 판단과 관계가 사라져 읽기 어렵고, 모든 내용을 문장으로 쓰면 나열이 길어진다. 이 파일은 두 형태의 위치를 목록과 표의 구조로 정한다.

## 사용처별 기본 어미

| 사용처 | 기본 어미 | 예 |
| --- | --- | --- |
| 정책서, 기획서, API 스펙, 설계서, 규칙 가이드, README, 튜토리얼, How-to, 설명 문서, Figma 화면 설명 | 한다체 | 서버는 요청을 거절한다. |
| GitHub Issue, Pull Request, Issue와 PR의 코멘트 | 합니다체 | 서버가 요청을 거절하도록 바꿨습니다. |
| Slack, Discord 같은 팀 메신저 | 해요체 | 서버가 요청을 거절하도록 바꿨어요. |
| 에이전트가 사용자에게 보내는 대화 답변 | 해요체 | 설정 파일을 수정했어요. |

- 한 결과물 안에서 기본 어미를 섞지 않는다.
- 코드 블록, 인용문과 화면 문구는 기본 어미 규칙에서 제외한다. 예시 블록 안의 어미는 [예시 블록](example-blocks.md)을 따른다.

## 문장과 명사형의 위치

| 위치 | 형태 |
| --- | --- |
| 제목 | 명사구 |
| 본문 문단 | 기본 어미 문장 |
| 문장 목록 | 기본 어미 문장 |
| 보충 목록 | 명사형 |
| 표의 셀 | 명사형 |
| 표 아래 설명 | 기본 어미 문장 |

### 문장 목록과 보충 목록 구분

목록의 종류는 목록 바로 앞 문장에 `다음`이 있는지로 정한다.

- **보충 목록**: 바로 앞 문장이 `다음`으로 목록을 가리키는 도입 문장인 목록이다. 도입 문장이 말한 내용의 대상, 조건, 예외, 근거, 영향이나 결과를 나열한다. 항목은 명사형으로 끝내고 마침표를 찍지 않는다.
- **문장 목록**: 보충 목록이 아닌 모든 목록이다. 각 항목이 독립된 규칙, 요구사항, 완료 조건, 절차 단계, 결정 사항이나 요청을 담는다. 항목은 기본 어미 문장으로 끝내고 마침표를 찍는다.
- 보충 목록의 도입 문장에는 `다음`과 나열하는 대상을 쓴다. `이 변경은 다음 문서 위치에 적용한다.`처럼 쓴다.
- 문장 목록 바로 앞 문장에는 `다음`을 쓰지 않는다.
- 문장 목록 항목 아래의 하위 목록은 도입 문장 없이 보충 목록으로 쓴다.
- 검토 체크리스트처럼 확인 질문을 나열하는 목록은 위치와 관계없이 의문문으로 쓴다.
- 참고 자료처럼 링크나 자료 이름만 나열하는 목록은 위치와 관계없이 `<종류>: <이름이나 링크>` 명사구로 쓴다.

```markdown
## 완료 조건

- 회원이 유효한 초대 코드를 검색하면 앱은 여행명, 기간과 참여 인원을 보여 준다.
- 회원이 이미 참여한 여행의 코드를 검색하면 앱은 참여 요청 없이 여행 화면으로 이동한다.

## 영향 범위

이 변경은 다음 문서 위치에 적용한다.

- `TRIP-02 여행 생성`의 오류 표
- `TRIP-04 여행 정보 수정`의 요청 표와 오류 표
```

### 명사형의 형태

보충 목록과 표의 셀은 항목의 내용에 따라 두 형태 중 하나로 쓴다.

| 항목의 내용 | 형태 | 예 |
| --- | --- | --- |
| 대상, 값, 범위, 이름 | 명사구 | `TRIP-02 여행 생성`의 오류 표 |
| 동작, 상태, 결과 | `-ㅁ`, `-음` 종결 | 기존 지출의 환율을 유지함 |

- 동작을 한자어 명사로 바꿔 끝내지 않는다. `환율 유지`가 아니라 `환율을 유지함`으로 쓴다.
- `-것`, `-하기`, `-됨`으로 끝내지 않는다. 피동이 필요한 결과는 주체를 세워 `서버가 값을 비움`으로 쓴다.
- 한 목록 안에서 명사구 항목과 `-ㅁ`, `-음` 항목을 섞지 않는다. 섞이면 목록을 둘로 나눈다.
- 명사형 항목 하나에는 사실 하나만 쓴다. 쉼표나 연결어미로 두 동작을 잇지 않는다.
- 명사형 항목은 12어절 이하로 쓴다. 더 길면 기본 어미 문장으로 바꿔 본문에 쓴다.

### 제목

- 제목은 명사구로 쓴다. `초대 코드 검색`처럼 쓰고 `초대 코드를 검색하기`, `초대 코드를 검색한다`로 쓰지 않는다.
- 같은 수준의 제목은 같은 구조의 명사구로 맞춘다.
- 제목은 30자 이하로 쓰고 물음표와 느낌표를 쓰지 않는다.
- 절차의 단계 제목에는 순서 번호를 붙인다.

## 기본 어미별 세부 규칙

### 한다체

| 용도 | 형태 | 예 |
| --- | --- | --- |
| 시스템 동작, 사실 | `-ㄴ다`, `-는다`, `-이다` | 서버는 요청을 거절한다. |
| 사용자의 의무 | `-해야 한다` | 회원은 약관에 동의해야 한다. |
| 사용자의 권한 | `-할 수 있다` | 관리자는 초대 코드를 복사할 수 있다. |
| 금지 | `-할 수 없다`, `-하지 않는다` | 확정된 여행에는 참여할 수 없다. |
| 절차 단계 | `-ㄴ다`, `-는다` | 설정 파일을 연다. |

- `-하도록 한다`, `-하게 된다`, `-되어진다`, `-하는 것이다`, `-하는 것이 좋다`, `-할 필요가 있다`로 끝내지 않는다.

### 합니다체

| 용도 | 형태 | 예 |
| --- | --- | --- |
| 사실, 현재 동작 | `-ㅂ니다`, `-습니다` | 서버는 요청을 거절합니다. |
| 완료한 작업 | `-했습니다` | 오류 표에 거절 조건을 추가했습니다. |
| 하지 못한 작업 | `-하지 못했습니다` | 클라이언트 연동은 확인하지 못했습니다. |
| 앞으로 할 작업 | 현재형과 시점 | 다음 PR에서 OpenAPI에 반영합니다. |
| 요청 | `-해 주세요` | 거절 기준이 맞는지 확인해 주세요. |

- `-하였습니다`는 `-했습니다`로 쓴다.
- `-할 예정입니다`, `-드립니다`, `-것 같습니다`, `-해 주십시오`로 쓰지 않는다. `공유드립니다`는 `공유합니다`로 쓴다.

### 해요체

| 용도 | 형태 | 예 |
| --- | --- | --- |
| 사실, 현재 동작 | `-아요`, `-어요`, `-이에요`, `-예요` | 서버가 요청을 거절해요. |
| 완료한 작업 | `-했어요` | 오류 표를 고쳤어요. |
| 앞으로 할 작업 | `-할게요`, 현재형과 시점 | 내일 배포할게요. |
| 요청 | `-해 주세요` | 오늘 안에 확인해 주세요. |
| 답이 필요한 질문 | `-할까요?`, `-인가요?` | 배포를 내일로 미룰까요? |

- `-하셨나요`처럼 높임을 겹치지 않는다. 상대를 높이는 표현은 요청의 `-해 주세요` 하나로 쓴다.
- `-ㅂ니다`, `-습니다`를 섞지 않는다.

## 시제

- 현재 기준과 시스템 동작은 현재형으로 쓴다.
- 완료한 작업은 과거형으로 쓴다.
- 앞으로 할 작업은 현재형에 시점이나 조건을 붙여 쓴다. `-할 예정`, `-하게 될 것`으로 쓰지 않는다.

## 의문문

- 한다체와 합니다체 결과물의 본문에는 의문문을 쓰지 않는다. 결정할 내용은 `-할지 정한다`, `-할지 정해야 합니다`로 쓴다.
- 해요체 결과물에서 상대의 답이 필요한 질문만 의문문으로 쓴다. 한 메시지에 질문은 번호를 붙여 나열한다.
- 검토 체크리스트처럼 확인 질문 목록이 목적인 목록은 의문문으로 쓴다.
