# 튜토리얼

처음 배우는 독자가 따라 하며 결과물 하나를 만드는 문서에 적용한다. 문서 유형은 [문서](document.md#문서-유형)의 튜토리얼이고, 기본 어미는 한다체다.

## 원칙

- 튜토리얼의 목적은 독자가 배우는 것이다. 작업을 끝내는 것이 목적이면 [How-to](how-to.md)로 쓴다.
- 독자가 처음부터 끝까지 막히지 않고 따라 하게 쓴다.
- 운영 환경과 공유 리소스를 바꾸는 단계는 넣지 않는다. 로컬 환경이나 실습용 환경에서 끝나게 쓴다.
- 작성자가 모든 단계를 직접 실행하고 기대 결과와 같은지 확인한 뒤 공유한다. 확인하지 못한 튜토리얼은 공유하지 않는다.

## 제목

- `<주제> 입문: <만드는 결과물>` 명사구로 쓴다. 예를 들어 `Terraform 입문: users.yml로 관리자 목록 출력`처럼 쓴다.

## 구조

다음 순서로 쓴다.

| 섹션 | 내용 | 형태 |
| --- | --- | --- |
| 개요 | 만드는 결과물과 걸리는 시간 | 문단, 2문장 이하 |
| 사전 준비 | 설치할 도구, 버전과 준비할 파일 | 도입 문장과 보충 목록 |
| 단계 | 결과물을 만드는 단계 | `### 1. <단계 이름>` 제목과 단계 본문 |
| 결과 확인 | 완성한 결과물과 확인 방법 | 문단과 기대 출력 블록 |
| 다음 문서 | 이어서 읽을 How-to, 레퍼런스와 설명 문서 | 링크 목록 |

- 개요는 `이 튜토리얼에서는 <결과물>을 만든다.`로 시작한다. `<개념>을 배운다`로 쓰지 않는다.
- 사전 준비가 없으면 `사전 준비` 섹션을 쓰지 않는다.

## 단계

- 단계는 10개 이하로 쓴다. 더 많으면 결과물을 나눠 튜토리얼을 둘로 쓴다.
- 단계 하나는 독자가 확인할 결과 하나를 만든다.
- 단계 본문은 동작 문장, [명령과 출력](../example-blocks.md#명령과-출력) 블록, 기대 결과 순서로 쓴다.
- 설명은 단계마다 한 문장까지 쓴다. 더 필요한 설명은 설명 문서를 링크한다.
- 선택지와 대안을 쓰지 않는다. 한 가지 방법만 쓴다.
- 앞 단계에서 만든 파일과 값을 다음 단계에서 그대로 쓴다.

다음은 가상 예시다.

````markdown
### 2. 관리자 목록 출력

다음 내용으로 `main.tf`를 만든다.

```hcl
locals {
  users  = { for u in yamldecode(file("users.yml")).users : u.name => u }
  admins = [for name, u in local.users : name if u.role == "admin"]
}
output "admins" { value = local.admins }
```

다음 명령을 실행한다.

```bash
terraform init
terraform apply
```

다음 출력이 나오면 이 단계를 마친 것이다.

```text
admins = [
  "sangcci",
]
```
````
