# 설명 문서

독자가 읽고 이해하도록 배경, 개념과 구조 선택의 이유를 설명하는 팀 내부 문서에 적용한다. 전환 설계처럼 바뀌는 구조를 설명하는 문서도 포함한다. 문서 유형은 [문서](document.md#문서-유형)의 설명이고, 기본 어미는 한다체다.

## 원칙

- 문서 하나는 질문 하나에 답한다. 질문은 `왜`나 `어떻게 동작하는가`로 쓴다.
- 개요에 질문의 답을 먼저 쓴다. 배경과 근거는 개요 다음에 쓴다.
- 절차, 명령 순서와 레퍼런스 표를 쓰지 않는다. 이 내용은 How-to와 레퍼런스에 쓰고 `관련 문서`에 링크한다.
- 결정의 주체는 `팀`으로 쓴다. `우리`, `저희`, `나`를 쓰지 않는다.
- H2 섹션은 6개 이하로 쓴다. 더 많으면 질문을 나눠 문서를 둘로 쓴다.

## 제목

- 질문을 명사구로 바꿔 쓴다. `<대상>을 <동작>하는 이유`, `<개념>의 동작 원리`, `<대상> 전환 설계`처럼 쓴다.

## 구조

설명 문서는 내용에 따라 두 구조 중 하나를 쓴다.

### 결정을 설명하는 문서

구조 선택의 이유와 전환 설계를 설명하는 문서는 다음 순서로 쓴다.

| 섹션 | 내용 | 형태 |
| --- | --- | --- |
| 개요 | 질문의 답과 바뀌는 결과 | 문단, 3문장 이하 |
| 배경 | 현재 구조와 문제 | 문단과 수치 |
| 검토한 선택지 | 선택지와 비교 기준별 결과 | 표 |
| 결정과 이유 | 고른 선택지와 이유 | 문단 |
| 바뀌는 구조 | 바뀐 뒤의 구조 | 다이어그램과 변경형 예시 블록 |
| 영향 | 바뀌는 대상과 감수하는 비용 | 도입 문장과 보충 목록 |
| 관련 문서 | 결정 기록, How-to, 레퍼런스 | 링크 목록 |

- `검토한 선택지` 표의 행은 선택지, 열은 비교 기준으로 쓴다. 셀에는 기준별 결과를 명사형으로 쓴다.
- 현재와 바뀐 뒤를 비교하는 표는 행을 7개 이하로 쓴다. 더 많으면 주제별로 표를 나누고 각 표 앞에 제목을 둔다.
- 결정을 아직 정하지 않았으면 제목 아래에 `> 논의 필요` 인용문을 두고 정할 내용을 링크한다. 정하기 전에 실행할 절차를 문서에 쓰지 않는다.

### 개념을 설명하는 문서

도구, 기술이나 시스템의 동작 원리를 설명하는 문서는 다음 순서로 쓴다.

| 섹션 | 내용 | 형태 |
| --- | --- | --- |
| 개요 | 개념이 하는 일 | 문단, 2문장 이하 |
| 정의 | 개념의 정의 | 문단, 2문장 이하 |
| 동작 원리 | 개념이 동작하는 순서와 구조 | 다이어그램과 문단 |
| 팀 시스템에서의 쓰임 | 팀 시스템이 개념을 쓰는 위치 | 문단과 레퍼런스 링크 |
| 관련 문서 | 튜토리얼, How-to, 레퍼런스 | 링크 목록 |

## 다이어그램과 예시

- 구조나 흐름을 설명하면 [Mermaid 다이어그램](../example-blocks.md#mermaid-다이어그램)을 하나 이상 둔다.
- 바뀌는 구조를 설명하면 [변경형 예시 블록](../example-blocks.md#변경형)을 쓴다.
- 코드 예시는 개념을 보여 주는 10줄 이하의 조각만 쓴다. 따라 하는 실습은 튜토리얼로 쓴다.
