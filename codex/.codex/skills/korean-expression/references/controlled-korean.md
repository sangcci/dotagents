# 한국어 통제 규칙

ASD-STE100의 구성을 한국어에 맞춘 규칙이다. 단어 하나에 뜻 하나를 정하고, 문장의 길이와 구조를 제한해 누가 읽어도 같은 뜻으로 이해하게 한다. 규칙 번호는 검토 코멘트에서 위반 위치를 가리킬 때 쓴다.

## 셈 기준

- 어절은 띄어쓰기로 나뉜 단위다. 백틱으로 감싼 식별자, 경로와 값은 1어절로 센다.
- 문장은 마침표, 물음표나 줄바꿈으로 끝나는 단위다. 목록 항목 하나는 문장 하나로 센다.

## 문장 규칙

### K1. 문장 길이

- 절차 단계와 요청 문장은 15어절 이하로 쓴다.
- 설명 문장은 20어절 이하로 쓴다.
- 길이를 넘으면 조건, 동작과 결과를 별도 문장으로 나눈다.

### K2. 한 문장, 한 내용

- 절차 단계 문장에는 동작 하나를 쓴다.
- 설명 문장에는 판단 하나를 쓴다.
- 한 문장의 절은 둘까지 쓴다. 조건절이나 원인절 하나와 주절 하나로 구성한다.
- `-며`, `-고`, `-는데`, `-면서`로 서로 다른 판단 두 개를 잇지 않는다.

### K3. 능동형 서술어

- 행위자가 있는 동작의 서술어는 능동형으로 쓰고 동작의 주체를 주어로 세운다.
- `만료되다`, `시작되다`처럼 행위자가 없는 변화는 `-되다` 형태로 쓴다.
- 피동형은 상태를 꾸미는 관형어에만 쓴다. `저장된 값`, `확정된 여행`은 쓰고 `값이 저장된다`는 `서버가 값을 저장한다`로 쓴다.
- `-되어지다`, `-지게 되다`처럼 피동을 겹치지 않는다.

### K4. 주체 명시

- 동작을 설명하는 문장에는 동작의 주체를 쓴다. 주체는 결과물 안에서 정한 이름 하나로 부른다. 예를 들어 `회원`, `관리자`, `앱`, `웹`, `서버`처럼 쓴다.
- 같은 주체가 이어지는 문장에서는 두 번째 문장부터 주체를 생략한다.

### K5. 명사 연쇄

- 조사 없이 잇는 명사는 3개까지 쓴다. `회원 탈퇴 데이터 삭제 정책`은 `회원이 탈퇴하면 데이터를 삭제하는 정책`으로 쓴다.
- 기능 이름, 화면 이름과 API 이름은 고유한 이름 하나로 보고 1개로 센다.

### K6. 동사의 명사화

- 동작은 동사로 쓴다. `설정 수행`, `검토 진행`, `배포 실시`는 `설정한다`, `검토한다`, `배포한다`로 쓴다.
- `-을 통해`, `-에 대해`, `-에 대한`, `-에 있어서`, `-함에 따라`, `-으로 인한`은 [통제 어휘](#통제-어휘)의 대체 표현으로 쓴다.

### K7. 조건과 시점

| 관계 | 형태 | 예 |
| --- | --- | --- |
| 조건 | `-면` | 코드가 만료되면 앱은 오류 화면을 보여 준다. |
| 시점 | `-ㄹ 때` | 회원이 처음 로그인할 때 앱은 약관 화면을 보여 준다. |
| 기간 | `-는 동안` | 회원이 여행에 참여하는 동안 앱은 지출 알림을 보낸다. |
| 원인 | `-므로`, `-기 때문에` | 코드를 다시 발급하지 않으므로 앱은 초대 정보를 계속 보관한다. |

- `-시`, `-할 시`, `-하는 경우`, `-의 경우`로 조건을 쓰지 않는다.

### K8. 부정

- 이중 부정을 쓰지 않는다. `-하지 않으면 안 된다`는 `-해야 한다`로, `없지 않다`는 `있다`로 쓴다.
- 부정은 서술어에 한 번만 쓴다.

### K9. 지시어

- `이것`, `그것`, `해당`, `위`, `아래`, `상기`, `전술한`으로 대상을 가리키지 않는다. `규칙 아래에 둔다`처럼 배치를 나타내는 `위`와 `아래`는 쓴다. 대상의 이름을 다시 쓰거나 링크한다.
- `이 문서`, `이 PR`, `이 API`처럼 지시 관형사 뒤에 명사를 쓴 표현은 쓴다.

### K10. 확정 여부

- 확인한 사실은 단정형으로 쓴다.
- 확인하지 못한 내용은 `확인하지 못했다`로 쓰고 이유를 붙인다.
- 원인이 확정되지 않은 분석은 `가설:`로 시작하는 문장으로 쓴다.
- `-것 같다`, `-듯하다`, `-로 보인다`, `아마`, `-할 수도 있다`를 쓰지 않는다.

### K11. 수치와 범위

- 정도를 나타내는 표현 대신 수치와 단위를 쓴다. `많을 때`는 `10,000건을 넘으면`으로, `빠르게`는 `1초 안에`로 쓴다.
- 나열은 항목을 모두 쓴다. 모두 쓰기 어려우면 `다음 3개`처럼 개수를 밝히고 나열한다.

### K12. 메타 표현과 강조

- 글의 흐름을 설명하거나 독자의 반응을 유도하는 말을 쓰지 않는다. `참고로`, `아시다시피`, `중요한 점은`, `결론적으로`, `기본적으로`, `사실`, `정말`, `꼭`을 쓰지 않는다.
- 굵은 글씨는 결과물 하나에 두 번까지 쓴다. 독자가 놓치면 잘못 판단하는 단어에만 쓴다.
- 이모지를 쓰지 않는다.

### K13. 문단

- 설명 문단은 6문장 이하로 쓴다.
- 문단의 첫 문장에 문단의 핵심 판단을 쓴다.

### K14. 약어와 외래어

- 약어는 처음 쓸 때 원어를 괄호에 함께 쓴다. `SSR(Server-Side Rendering)`처럼 쓰고 약어와 괄호 사이를 띄지 않는다.
- 다음 약어는 풀어 쓰지 않는다: API, PR, URL, HTTP, JSON, ID, UI, DB, CI.
- 외래어는 업계에서 많이 쓰는 표기를 쓴다. `프론트엔드`, `컨테이너`, `메시지`처럼 쓴다.
- 영어 동사를 한글로 옮긴 `리졸브하다`, `컨펌하다`, `픽스하다`를 쓰지 않는다.

### K15. 문장부호

- 항목을 나열할 때는 쉼표, 접속사나 줄바꿈을 쓴다. 가운데점(U+00B7)을 쓰지 않는다.
- 엠대시로 원인, 결과나 부연 설명을 압축하지 않는다. 관계에 맞는 접속사, 콜론이나 별도 문장으로 쓴다.
- 괄호는 한 겹만 쓴다. 괄호 안에 문장을 쓰지 않는다.
- 한다체와 합니다체 결과물에는 느낌표를 쓰지 않는다.
- 인용문과 코드 식별자에 포함된 문장부호는 바꾸지 않는다.
- 코드 식별자, 경로, 설정값, 상태값, API 경로와 화면 식별자는 백틱으로 감싼다.
- 버튼 이름, 안내 문구와 오류 문구처럼 화면에 그대로 표시하는 문구는 백틱으로 감싼다. 작은따옴표와 큰따옴표로 감싸지 않는다.
- 버튼은 `` `<버튼 문구>` 버튼``으로 쓴다. `` `이 여행 참여하기` 버튼을 누른다.``처럼 쓴다.
- 화면 이름은 백틱 없이 쓴다. `여행 생성 화면`처럼 쓴다.

## 통제 어휘

### 단어 하나, 뜻 하나

다음 동사는 표의 뜻으로만 쓴다.

| 단어 | 뜻 | 대신 쓰지 않는 단어 |
| --- | --- | --- |
| 확인하다 | 사실이나 상태를 직접 보고 맞는지 판단함 | 체크하다 |
| 검증하다 | 테스트나 실행으로 동작을 입증함 | 테스트해 보다 |
| 검토하다 | 판단하려고 내용을 읽음 | 리뷰하다(코드 리뷰 제외) |
| 정하다 | 선택지 중 하나를 고름 | 픽스하다, 컨펌하다 |
| 만들다 | 새 대상을 존재하게 함 | 생성하다(기능 이름 제외) |
| 추가하다 | 기존 대상에 항목을 더함 | 넣다 |
| 삭제하다 | 저장된 데이터를 지움 | 날리다 |
| 제거하다 | 코드, 설정이나 구성 요소를 뺌 | 걷어내다 |
| 수정하다 | 잘못된 내용을 고침 | 픽스하다 |
| 변경하다 | 기준이나 값을 다른 것으로 바꿈 | 바꿔치기하다 |
| 반영하다 | 정한 내용을 문서나 코드에 적용함 | 녹이다 |

기능 이름에는 명사 `생성`, `수정`, `삭제`를 쓴다. 예를 들어 `여행 생성 API`처럼 쓰고, 서술어에는 위 표의 동사를 쓴다.

### 금지 표현과 대체 표현

| 금지 표현 | 대체 표현 |
| --- | --- |
| 진행하다, 수행하다, 실시하다 | 본동사. `검토를 진행한다`는 `검토한다`로 씀 |
| 처리하다(동작이 불분명할 때) | 실제 동작. `저장한다`, `거절한다`, `무시한다` |
| 정상 처리 | 실제 결과. `200 응답을 반환한다` |
| 적절히, 알맞게, 충분히 | 기준이나 수치 |
| 필요시, 필요한 경우 | 조건을 `-면`으로 씀 |
| 가능하면, 가급적 | 규칙을 확정해 단정형으로 씀 |
| 관련 내용, 관련 사항 | 대상의 이름 |
| 해당 | 대상의 이름, 지시 관형사 `이` |
| 등, 등등 | 항목을 모두 나열함 |
| 및 | 쉼표, `와`, `과` |
| -을 통해 | `-으로`, `-해서` |
| -에 대해, -에 대한 | 목적어 조사 `을`, `를` 또는 구체적인 관계 |
| -에 있어서 | `-에서`, `-할 때` |
| -함에 따라 | `-하므로`, `-하면` |
| -으로 인한 | `-때문에 생긴` |
| 가능하다, 불가하다 | `-할 수 있다`, `-할 수 없다` |
| 확인 필요 | 확인할 사람과 대상. `서버 담당자가 만료 시간을 확인한다` |
| 이슈(문제의 뜻) | 문제. GitHub Issue는 `Issue`로 씀 |
| 케이스 | 경우, 사례 |
| 니즈 | 요구 |
| 레퍼런스 | 참고 자료 |
| 디펜던시 | 의존성 |
| 개선하다, 최적화하다(결과가 없을 때) | 바뀐 결과와 수치 |
| 지원하다(범위가 없을 때) | 지원 대상과 범위 |
| 대응하다(동작이 없을 때) | 실제 동작 |

### 용어 통일

- 같은 대상은 결과물 전체에서 같은 용어로 부른다. `업로드`, `첨부`, `추가`를 섞지 않는다.
- 저장소나 프로젝트에 용어집이 있으면 용어집의 용어를 쓴다.
- 기술 용어는 공식 문서의 표기와 대소문자를 따른다.

## 검사 항목

초안을 쓴 뒤 다음 항목을 차례로 확인한다.

- K1: 15어절이 넘는 절차 문장과 20어절이 넘는 설명 문장이 없는가?
- K2: 한 문장에 동작이나 판단이 둘 이상 있지 않은가?
- K3: 행위자가 있는 동작을 피동형 서술어로 쓴 문장이 없는가?
- K4: 앞 문장과 주체가 다른데 주체를 생략한 동작 문장이 없는가?
- K5: 조사 없이 이어진 명사가 4개 이상인 곳이 없는가?
- K6, 통제 어휘: 금지 표현이 남아 있지 않은가?
- K7: `-시`, `-경우`로 쓴 조건이 없는가?
- K9: 이름 없이 대상을 가리키는 지시어가 없는가?
- K10: 추측 표현이 없는가?
- K11: 정도 표현과 `등`으로 끝나는 열린 나열이 없는가?
- K12: 메타 표현, 이모지와 세 번 이상의 굵은 글씨가 없는가?
- K15: 가운데점과 엠대시가 없고, 화면 문구와 식별자를 백틱으로 감쌌는가?
