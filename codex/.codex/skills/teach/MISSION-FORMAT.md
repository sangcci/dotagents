# MISSION.md 형식

`MISSION.md`는 워크스페이스 루트에 둡니다. 사용자가 이 주제를 배우는 _이유_를 담습니다. 다음에 무엇을 가르칠지, 어떤 자료를 보여 줄지, 어떤 연습을 설계할지는 모두 이 문서로 거슬러 올라갈 수 있어야 합니다.

## 템플릿

```md
# 미션: {주제}

## 이유
{1~3문장. 사용자가 쫓는 구체적인 현실의 목표. 이 기술을 갖추면 삶이나 일이 어떻게 달라지는가? "X를 이해하려고"처럼 추상적으로 쓰지 않고 바탕에 있는 결과까지 파고든다.}

## 성공의 모습
- {사용자가 할 수 있게 될 구체적이고 관찰 가능한 일}
- {또 다른 구체적인 일}
- {...}

## 제약
- {시간, 예산, 이미 있는 일정, 학습 선호처럼 접근을 한정하는 모든 조건}

## 범위 밖
- {사용자가 지금은 쫓지 않기로 한 인접 주제. 학습 근접 발달 영역을 지킨다}
```

## 규칙

- **워크스페이스 하나에 미션 하나입니다.** 사용자가 서로 무관한 두 가지를 배우려면 워크스페이스가 둘입니다.
- **추상보다 구체입니다.** "더 건강해지기"보다 "10월까지 하프 마라톤 완주"가, "Rust 배우기"보다 "팀에 Rust CLI 배포"가 낫습니다.
- **모호함에는 되묻습니다.** 사용자가 이유를 말하지 못하면 쓰기 전에 인터뷰합니다. 나쁜 미션은 없는 미션보다 나쁩니다.
- **현실이 바뀌면 고칩니다.** 미션은 바뀝니다. 사용자의 목표가 움직이면 이 파일을 갱신합니다. 낡은 미션이 이후 세션을 이끌게 두지 않습니다.
- **짧게 유지합니다.** `MISSION.md`가 한 화면을 넘으면 나침반이 아니라 계획이 된 것입니다.
