# Glossary Writing Guide

## 목적

이 문서는 서비스의 기준 용어와 맥락별 표현을 일관된 형식으로 관리하기 위한 기준을 정의한다. 근거, 상태와 공통 문체는 [공통 문서 작성 가이드](<../../Projects/finditem/DOCS/guide/공통 문서 작성 가이드.md>)를 따른다.

## 문서 역할

용어집에는 팀이 공통으로 사용하는 기준 용어를 정의하고, 같은 개념을 사용자와 제품, 도메인 및 화면에서 어떻게 표현하는지 기록한다.

- 팀이 공통으로 사용하는 기준 용어
- 사용자와 제품, 도메인 및 화면에서 사용하는 맥락별 용어
- 혼동을 막기 위해 사용하지 않는 용어
- 유형값과 상태값
- 화면에 표시하는 값

권한, 검증, 상태 전환과 처리 규칙은 용어집에 작성하지 않고 관련 정책서를 링크한다.

## 문서 구조

용어집은 `용어집/용어집.md` 한 곳에서 관리하고 업무 영역별 섹션으로 나눈다. 같은 용어를 여러 영역에 중복해서 정의하지 않는다.

### 용어

기준 용어, 정의와 맥락별 용어를 하나의 표로 작성한다. 사용하지 않는 용어도 같은 표에 기록한다.

```markdown
## [업무 영역]

| 기준 용어 | 정의 | 사용자(제품) 용어 | 도메인 용어 | 화면 용어 | 사용하지 않는 용어 |
| --- | --- | --- | --- | --- | --- |
| [기준 용어] | [다른 용어와 구분되는 정의] | [사용자가 이해하는 표현] | [도메인에서 사용하는 표현] | [화면에 표시하는 표현] | [혼동을 일으켜 사용하지 않는 표현] |
```

정의는 해당 용어만으로 이해할 수 있게 작성한다. 구현 타입, 저장 위치와 처리 절차는 포함하지 않는다.

맥락별로 기준 용어와 다른 표현을 사용하지 않으면 기준 용어를 반복해서 작성하지 않고 `-`로 표시한다. 화면에 표시하는 문구가 화면이나 상황에 따라 달라지면 대표 문구를 임의로 선택하지 않고 관련 화면 정의서를 링크한다.

사용하지 않는 용어가 여러 개이면 쉼표로 구분한다. 사용하지 않는 이유나 대체 기준을 별도로 설명해야 하면 표 바로 아래에 작성한다.

### 유형값과 상태값

업무 영역에서 사용하는 유형값이나 상태값이 있으면 한글 값, 영문 값, 화면 표시값과 의미를 함께 작성한다.

```markdown
### 유형값과 상태값

| 구분 | 영문 식별자 | 한글 값 | 영문 값 | 화면 표시값 | 의미 |
| --- | --- | --- | --- | --- | --- |
| [유형 또는 상태] | `[english_identifier]` | [한글 값] | `[VALUE]` | [화면 표시값] | [값의 의미] |
```

화면 표시값이 언어 또는 화면에 따라 다르면 대표값을 임의로 선택하지 않고 관련 다국어 문서나 화면 정의서를 링크한다.

## 용어 작성 원칙

- 팀이 공통으로 구분해서 사용해야 하는 업무 개념만 등록한다.
- 일상적인 단어, 특정 화면에서만 사용하는 문구와 내부 클래스명은 등록하지 않는다.
- 하나의 개념에는 하나의 기준 용어를 사용한다.
- 회의와 공통 문서에서는 기준 용어를 사용한다.
- 사용자와 제품, 도메인 또는 화면에서 다른 표현이 필요하면 새 용어로 중복 등록하지 않고 해당 기준 용어의 행에 기록한다.
- 같은 개념을 가리켜 혼동을 일으키는 표현은 해당 기준 용어의 `사용하지 않는 용어`에 기록하고 사용하지 않는다.
- API 용어는 용어 표의 관리 대상으로 삼지 않는다.
- 유형값과 상태값의 의미는 다른 값과 구분되는 조건이 드러나게 작성한다.

## 완료 전 확인 목록

- 기존 용어와 의미가 중복되지 않는가?
- 각 개념에 기준 용어가 하나만 지정되어 있는가?
- 사용자와 제품, 도메인 및 화면에서 사용하는 표현이 올바른 기준 용어에 연결되어 있는가?
- 혼동을 일으키는 표현이 `사용하지 않는 용어`에 기록되어 있는가?
- 유형값과 상태값의 영문 식별자 및 영문 값이 실제 계약과 일치하는가?
- 유형값과 상태값을 빠짐없이 작성했는가?
- 정의에 정책이나 구현 절차를 포함하지 않았는가?
