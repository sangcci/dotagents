# 에이전트와 개발하는 방식

## 원칙

에이전트에게 코드를 쓰게 하는 시대에 개발자가 맡는 일은 아키텍트의 일이다. 요구사항에 반박하고, 무엇을 포기할지 정하고, 그 제약 안에서 에이전트가 일하게 하고, 결과를 검증한다. 에이전트는 요구사항을 그대로 수행하고 비기능 요구사항의 균형을 스스로 정해 버리는 경향이 있으므로, 이 판단은 사람이 한다.

- 설계는 사람이 이해할 때까지 묻고 답한다. 구현은 합의한 설계를 낮은 비용으로 옮기는 단계이고, 토큰은 검증과 리뷰에 더 쓴다.
- 코드를 한 줄씩 읽는 일은 에이전트에게 맡긴다. 대신 에이전트가 스스로 채점하고 고칠 수 있는 피드백 루프를 갖춘다.
- 사람이 끝까지 이해해야 하는 것은 데이터 모델, 포기한 트레이드오프, 테스트하는 경계(seam), 머지를 되돌릴 수 있는지다.

## 설계

계획이나 아이디어는 `grilling`으로 검증한다. 에이전트의 의도와 사람의 이해가 맞아떨어질 때까지 질문하고, 합의한 내용은 구현 전에 확정한다.

요구사항만 합의하면 부족하다. 에이전트는 명시한 요구사항을 모두 만족시키려다 아키텍처를 대신 정한다. 다음을 질문에 포함해 사람이 정한다.

- 이 요구사항이 성능, 보안, 하위 호환성 중 무엇을 희생하는가?
- 데이터 모델은 어떤 모양인가? 하위 호환이 필요한가, 필요하다면 옛 버전을 언제 지우는가?
- 요구사항을 줄이거나 비동기 같은 우회로 비용을 낮출 수 있는가?

모듈은 작은 인터페이스 뒤에 많은 동작을 두는 깊은 모듈로 설계한다. 판단 어휘는 `codebase-design`이 정한다. 같은 일을 하는 얕은 모듈 여러 개보다 큰 상자 하나가 테스트와 에이전트의 탐색에 유리하다.

## 구현

설계가 끝났으면 추론 강도(effort)를 낮춰서 구현한다. 어려운 판단은 설계에서 이미 끝났다.

`tdd`는 테스트할 seam을 사용자와 먼저 합의하고 그곳에서만 테스트를 쓴다. 단위 테스트를 모든 함수에 쓰지 않고, 깊은 모듈의 인터페이스를 테스트 표면으로 삼아 내부 리팩터링에도 살아남는 테스트를 쓴다. 모듈을 깊게 만든 뒤에는 얕았을 때의 단위 테스트를 지운다.

## 검증과 리뷰

추론 강도를 높이고 토큰을 여기에 쓴다. 구현 에이전트는 탐색과 디버깅으로 컨텍스트가 가득 차지만 리뷰 에이전트는 diff만 받으므로, 규약 점검은 `diff-review`에 맡긴다. `diff-review`는 Standards와 Spec 두 축을 새 컨텍스트의 서브에이전트로 따로 돌린다. 완료를 보고하기 전에는 `verification-before-completion`으로 검증 근거를 확인한다.

피드백 루프는 에이전트가 실행할 수 있는 검사(타입, 린트, 테스트)가 있어야 돌아간다. 검사가 없어서 에이전트가 실수를 스스로 잡지 못했다면 `retro`로 그 검사를 만든다.

## 머지

머지 전에 사람이 읽는 것은 `pr` 본문의 Summary와 Merge Danger다.

- 되돌릴 수 있는 변경(two-way door)이면 실패해도 롤백으로 끝난다.
- 되돌릴 수 없는 변경(one-way door)이면 사람이 영향 범위를 이해한 뒤에 머지한다. 데이터 삭제, 스키마 변경, 외부에 공개된 계약의 변경이 여기에 속한다.

## 컨텍스트 관리

컨텍스트가 길어지면 에이전트가 맥락을 놓치기 시작한다. 구현 중에 쓸 수 있는 구간은 대략 15만 토큰이다. 단계가 끝나는 지점에서만 다음을 위에서부터 판단한다. 단계 중간에는 계속하거나 남은 일을 서브에이전트로 쪼갠다.

1. 다음 단계가 이 세션의 추론 과정을 그대로 필요로 하거나 남은 구간에 들어가면 계속한다. 설계에서 구현으로 넘어가는 경우가 대표적이다.
2. 지금까지의 내용이 다음 단계와 무관하면 `/clear`한다.
3. 다른 도구, 다른 디렉터리, 다른 사람에게 넘기거나 부수 작업을 떼어낼 때는 요약 파일을 쓴다.
4. 자리를 비워도 되는 범위가 분명한 일은 서브에이전트에 맡긴다. 자동 리뷰가 대표적이다.
5. 그 밖에는 `/compact`한다. 다음 단계에 필요한 내용을 지시에 적는다.

`/clear`는 되돌릴 수 없다. 관련 있는 맥락을 지우면 구현한 이유를 잃고, diff를 읽어도 되찾을 수 없다.
